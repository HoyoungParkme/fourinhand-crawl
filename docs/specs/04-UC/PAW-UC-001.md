# USECASE (Cockburn)

## 0. 이 문서의 형식

Cockburn 형식을 따른다. 유스케이스마다 12행 표(범위·수준·액터·보장 등), 기본 흐름, 확장을 둔다. 확장 번호 `2a`는 「기본 흐름 2단계에서 갈라지는 첫 번째 경우」다.

| ID 접두 | 뜻 |
|---|---|
| `UC-H` | 입양 희망자(사람)의 사용자 목표 |
| `UC-A` | 배포자의 사용자 목표 |
| `UC-S` | 하위기능 — 여러 유스케이스가 함께 쓰는 단계. 앱이 스스로 하는 일 |

범위는 두 가지다. **앱** = 설치된 데스크톱 프로그램. **배포** = 저장소·GitHub Actions·Releases·설치 파일.

## 2. 사용자 목표 수준 유스케이스

#### UC-H1 켜서 큰 고양이 목록 보기

| 항목 | 내용 |
|---|---|
| 범위 | 앱 |
| 수준 | 사용자 목표 |
| 주 액터 | 입양 희망자 |
| 이해관계자와 관심사 | 입양 희망자: 기다리지 않고 8kg 이상만 본다 · 포인핸드: 요청이 몰리지 않는다 · 보호소: 정확한 공고로 문의가 온다 |
| 사전조건 | 앱이 설치되어 있다 |
| 최소 보장 | 실패해도 앱이 꺼지지 않고, 이유와 다시 시도할 방법을 보여준다. 일부만 받은 목록을 전부인 것처럼 보여주지 않는다 |
| 성공 보장 | 기준(기본 8kg) 이상인 보호중 고양이가 무거운 순 카드로 보이고, 마릿수와 마지막으로 받은 시각이 보인다 |
| 트리거 | 입양 희망자가 시작 메뉴에서 앱을 연다 |
| 패키지 | 탐색 |
| 포함(include) | [[#UC-S1]] · [[#UC-S3]] |
| 확장점(extension point) | 카드에서 바로 가기 → [[#UC-H4]] · 카드 누르기 → [[#UC-H3]] |
| 일반화 | — |

**기본 흐름**
1. 입양 희망자가 앱을 연다
2. 앱이 보호중 고양이를 받아온다([[#UC-S1]]). 받는 동안 받은 건수를 보여준다
3. 앱이 기본 조건(8kg 이상 · 전체 기간 · 전국 · 무거운 순)으로 거른다([[#UC-S3]])
4. 앱이 카드 목록과 「N마리」, 마지막으로 받은 시각을 보여준다. 카드마다 공고 종료일로 「공고중」·「보호중」 배지를 붙인다
5. 입양 희망자가 목록을 훑어본다

**확장**
- **2a. 받아오기 실패** (인터넷 끊김 · 포인핸드 응답 없음 · 응답 형식이 예상과 다름)
  - 2a1. 앱이 「포인핸드에 연결하지 못했어요」와 이유, 「다시 시도」 버튼을 보여준다
  - 2a2. 입양 희망자가 「다시 시도」를 누르면 2로 돌아간다
- **2b. 몇 쪽 받다가 중간에 실패**
  - 2b1. 받은 일부로 목록을 만들지 않고 2a와 같이 처리한다 — 목록이 빠진 줄 모르고 보게 되면 「8kg 이상 누락 0건」을 지킬 수 없다. 전체를 다시 받는 데 3초 남짓이라 다시 시도의 부담이 작다(고객 결정)
- **4a. 걸린 아이가 0마리**
  - 4a1. 빈 화면 대신 「조건에 맞는 아이가 없어요」와 지금 조건(지역·기간·몸무게 기준)을 보여준다
- **4b. 사진을 못 불러옴**
  - 4b1. 사진 자리에 빈 그림을 보여주고 카드는 그대로 둔다

**기본 흐름**
1. 입양 희망자가 지역 선택을 연다. 시·도마다 옆에 지금 조건으로 걸리는 마릿수가 보인다
2. 입양 희망자가 시·도를 고른다
3. 앱이 다시 받아오지 않고 새 조건으로 거른다([[#UC-S3]]). 목록과 「N마리」가 바뀐다
4. 입양 희망자가 기간(전체·1년·6개월·3개월), 몸무게 기준(0.1kg 단위), 정렬(무거운 순·등록일 최신순)도 같은 방식으로 바꾼다. 바꿀 때마다 3을 한다

**확장**
- **2a. 「지역 미상」을 고름**
  - 2a1. 보호소 시·도가 빈 값인 아이만 보인다
- **3a. 걸린 아이가 0마리**
  - 3a1. [[#UC-H1]] 4a와 같다
- **4a. 몸무게 기준에 숫자가 아닌 값이나 음수를 넣음**
  - 4a1. 앱이 입력칸에 잘못된 값임을 표시하고, 목록은 마지막으로 올바르던 기준으로 둔다

#### UC-H3 한 아이 자세히 보기

| 항목 | 내용 |
|---|---|
| 범위 | 앱 |
| 수준 | 사용자 목표 |
| 주 액터 | 입양 희망자 |
| 이해관계자와 관심사 | 입양 희망자: 포인핸드에 가기 전에 정보를 충분히 본다 · 보호소: 문의 전에 기본 정보를 알고 온다 |
| 사전조건 | 목록에 카드가 하나 이상 있다 |
| 최소 보장 | 상세를 닫으면 보던 목록 위치와 조건이 그대로다 |
| 성공 보장 | 그 아이의 사진 최대 3장과 나머지 정보가 모두 보이고, 몸무게는 해석값과 원래 값이 함께 보인다 |
| 트리거 | 입양 희망자가 카드를 누른다 |
| 패키지 | 탐색 |
| 포함(include) | — |
| 확장점(extension point) | 「포인핸드에서 보기」·「원문 공고」 → [[#UC-H4]] |
| 일반화 | — |

**기본 흐름**
1. 입양 희망자가 카드를 누른다
2. 앱이 상세 보기를 연다 — 사진 최대 3장, 품종, 색, 중성화 여부, 특징, 발견 장소, 보호소 이름·주소·전화, 관할 기관, 공고번호, 공고 기간, 상태 배지
3. 몸무게는 「9kg (원래 값: 9.00(Kg))」처럼 해석값과 원래 문자열을 함께 보여준다
4. 입양 희망자가 사진을 넘겨 본다
5. 입양 희망자가 상세를 닫는다. 앱이 보던 목록 위치로 돌아간다

**확장**
- **2a. 사진이 1장뿐이거나 없음**
  - 2a1. 있는 사진만 보여준다. 하나도 없으면 빈 자리 그림 하나
- **2b. 값이 빈 항목(예: 특징 없음)**
  - 2b1. 그 줄에 「정보 없음」을 보여준다. 줄을 숨기지 않는다 — 없는 건지 앱이 빠뜨린 건지 구분되게
- **3a. 몸무게가 드문 값(예: 15kg)**
  - 3a1. 값을 바꾸지 않고 그대로 보여준다. 판단은 입양 희망자가 원래 값과 사진으로 한다

**연관**: [[PAW-PRD-001#R2]] · [[PAW-PRD-001#R8]] · [[PAW-SCN-001#S3]]

  - 1b1. 「원문 공고」 링크를 보여주지 않는다. 「포인핸드에서 보기」는 그대로 있다

| 성공 보장 | 지금 포인핸드 기준 목록이 지금 조건으로 걸러져 보이고, 마지막으로 받은 시각이 방금으로 바뀐다 |

**기본 흐름**
1. 입양 희망자가 「새로고침」을 누른다
2. 앱이 「새로고침」 버튼을 누를 수 없게 바꾼다
3. 앱이 다시 받아온다([[#UC-S1]])
4. 앱이 지금 조건(지역·기간·기준·정렬)을 유지한 채 거른다([[#UC-S3]])
5. 앱이 목록·마릿수·받은 시각을 바꾸고 버튼을 되살린다

**확장**
- **1a. 받는 중에 누름**
  - 1a1. 버튼이 눌리지 않는다. 요청이 겹쳐 나가지 않는다
- **3a. 받아오기 실패**
  - 3a1. 앱이 **이전 목록과 이전 받은 시각을 그대로 둔 채** 실패 이유와 「다시 시도」를 보여준다 — 이전 목록은 그 시각 기준으로 다 받은 목록이고, 받은 시각이 그대로라 오래된 목록임을 알 수 있다(고객 결정)
  - 3a2. 버튼을 되살린다
- **4a. 고른 시·도나 「지역 미상」이 새 데이터에 없음**
  - 4a1. 지역 조건을 「전국」으로 돌리고 그 사실을 알린다

#### UC-H6 설치하기

| 항목 | 내용 |
|---|---|
| 범위 | 배포 |
| 수준 | 사용자 목표 |
| 주 액터 | 입양 희망자 |
| 이해관계자와 관심사 | 입양 희망자: 개발 도구·관리자 권한 없이 설치한다 · 배포자: 「설치가 안 돼요」 문의가 없다 |
| 사전조건 | GitHub Releases 링크를 받았다. Windows 10·11 64비트 |
| 최소 보장 | 설치가 실패하면 반쯤 깔린 상태가 남지 않는다. 이전 버전이 있었다면 그대로 쓸 수 있다 |
| 성공 보장 | 시작 메뉴에 바로가기가 생기고, 「앱 제거」 목록에 등록된다 |
| 트리거 | 입양 희망자가 `setup.exe`를 실행한다 |
| 패키지 | 설치·배포 |
| 포함(include) | — |
| 확장점(extension point) | — |
| 일반화 | — |

**기본 흐름**
1. 입양 희망자가 Releases 링크에서 `setup.exe`(20MB 이하)를 내려받는다
2. 입양 희망자가 `setup.exe`를 실행한다
3. Windows가 「Windows의 PC 보호」 창을 띄운다. 입양 희망자가 안내대로 「추가 정보 → 실행」을 누른다
4. 설치 마법사가 현재 사용자 계정에 설치한다. 관리자 비밀번호를 묻지 않는다
5. 설치가 끝나고 시작 메뉴에 바로가기가 생긴다

**확장**
- **3a. 「추가 정보」를 못 찾음**

| 성공 보장 | 등록일 2020-01-01~오늘의 보호중 고양이 전부가 공고번호 중복 없이, 몸무게 해석값과 함께 있다 |

**기본 흐름**
1. 앱이 포인핸드 API에 요청한다 — 고양이 · 보호중 · 등록일 2020-01-01~오늘 · 1000건 · 첫 쪽. 조건 값의 공백은 `+`로 인코딩한다
2. 포인핸드 API가 최대 1000건의 JSON 배열을 준다
3. 앱이 각 건의 몸무게를 해석한다([[#UC-S2]])
4. 앱이 지금까지 받은 건수를 진행 상태로 알린다
5. 받은 건수가 1000이면 0.3초 쉬고 다음 쪽으로 1을 한다. 다음 쪽은 앞 쪽과 50건을 겹쳐 받는다 — 받는 사이 앞쪽에서 빠진 아이가 있어 줄이 당겨져도 뒤 아이를 놓치지 않게. 1000보다 적으면 끝낸다
6. 앱이 공고번호가 같은 건(겹쳐 받은 건 포함)을 하나만 남기고 결과로 돌려준다

**확장**
- **1a. 이미 받는 중**
  - 1a1. 새로 요청하지 않고 그 받기가 끝나기를 기다려 같은 결과(성공이든 실패든)를 돌려준다 — 화면을 다시 불러오는 등으로 겹쳐 불려도 포인핸드에 요청이 두 번 나가지 않게
- **2a. 응답이 없음** (한 요청이 15초 넘게 걸림)
  - 2a1. 실패로 끝낸다
- **2b. 오류 응답이거나 JSON 배열이 아님**
  - 2b1. 실패로 끝낸다 — 포인핸드가 주소나 형식을 바꿨을 수 있다
- **2c. 건은 왔는데 한 건도 옮기지 못함** (칸 이름·날짜 모양이 바뀜)
  - 2c1. 형식 이상으로 실패로 끝낸다
- **3a. 공고번호가 없거나 등록일·공고 기간을 못 읽는 건**
  - 3a1. 그 건만 버린다. 링크를 만들거나 기간으로 거를 수 없어서다
- **5a. 쪽 수가 비정상적으로 많음** (20쪽, 즉 2만 건 가까이 넘김)
  - 5a1. 멈추고 실패로 끝낸다 — API가 쪽 번호를 무시하고 같은 결과를 계속 줄 때 끝없이 요청하지 않게
- **6a. 다 받았는데 한 마리도 없음**
  - 6a1. 형식 이상으로 실패로 끝낸다 — 요청 모양이 어긋나면 포인핸드는 빈 배열을 준다. 빈 목록으로 이전 목록을 지우지 않는다
